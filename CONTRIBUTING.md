# Как попасть в репозиторий

Коротко: сначала задача, потом ветка, потом гейт. Ничего не вливается «просто так».

1. **Issue — первым.** Задача заводится в трекере проекта: что меняем и зачем. Без неё
   правка не рассматривается — иначе неясно, что считать готовым.
2. **Ветка от `main`**, один пункт — одна ветка: `feat/…`, `fix/…`, `docs/…`.
3. **Гейт перед сдачей** — из каталога `site/`:

   ```sh
   npm run verify && npm run test:coverage && npm run build
   node bin/validate.mjs      # 0 ошибок: рукопись и канон не должны разъехаться
   ```

   Красный гейт — не повод спорить с гейтом; изменения в тестах объясняются в описании правки.
4. **Дизайн-документы и ADR в репозиторий не добавляются.** Ни `docs/`, ни `adr/`: решение живёт
   страницей решения и комментарием к задаче, и нигде больше.
5. **Текст книги — отдельная лицензия.** Принятая правка в книгу несёт ту же передачу исключительного
   права автору, которую сайт просит у читателя: правила и текст — на [`/rules`](https://book.semirov.dev/rules).
6. **Код** — Apache-2.0 ([LICENSE](LICENSE)); отправляя правку, вы соглашаетесь, что она выходит под этой
   лицензией, а `NOTICE` остаётся на месте.
