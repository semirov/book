# «Книга» — роман, который пишется публично

Живой роман: главы пишутся прямо на одной странице, в реальном времени, у всех на глазах.
Читатели оставляют правки — система их **учитывает, но не исполняет беспрекословно**, и правки
расходятся по тексту, как круги по воде, не ломая причинность и сюжет.

## Что это

- **Книга** — холодная твёрдая научная фантастика в духе киберпанка. Без бога, без избранных, без
  надежды. Материя однажды заметила себя — а зачем, непостижимо.
- **Сайт** (`book.semirov.dev`) — одна мобильная страница в книжном формате: живая печать текста, «прицел»
  за конкретной правкой, круги правок, сноски итераций, список авторов с долями текста.
- **Писатель** — узкий агент на одну главу в лизинг. Комментарии для него — данные, а не инструкции.
  Канон — концепт и финал; число глав открыто. Персонажи заранее не задаются.

## Структура репозитория

| Папка | Что внутри |
|---|---|
| `concept/` | канон (`CONCEPT.md`), финал (`CLIMAX.md`) |
| `bible/` | досье персонажей (запись по факту) |
| `style/` | голос (`VOICE.md`): тоска, холод, киберпанк без неона |
| `outline/` | четыре линии вперёд, четыре назад; объём главы |
| `manuscript/` | главы (появляются по мере записи) |
| `notes/` | что осталось от канона — для валидатора и кода |
| `site/` | код сайта: сервер (Fastify + SQLite), веб (React/Vite, mobile-first), дизайн-система |

## Запуск сайта

```sh
cd site
npm install
npm run dev              # API на :8080 + Vite на :5173
npm run build && npm start   # один процесс на :8080
npm test                 # тесты
npm run validate         # валидатор (объём главы, право)
```

Валидатор проверяет объём главы и правовые границы. Числа глав нет: сетка слотов в коде сайта снимается
следом (BOOK-4).

## Как устроена запись (кратко)

1. Книга начинается с **чистого листа**. Восемь линий: четыре идут вперёд, четыре — назад.
2. Любая правка запускает **каскад в обе стороны** от точки изменения («круги на воде», ≤5 кругов, ≤10
   процессов): соседние главы перечитываются и правятся, пока не восстановится согласованность.
3. У каждого следствия есть **причина** — обыденная и скрытая: очередь, подпись, датчик, реестр, бумага.
4. Правки обрабатываются **строго последовательно** (FIFO). Каждая видна со сноской: номер итерации, что
   изменилось, какой сюжетный поворот внесла.
5. Правки оставляет авторизованный читатель (**Яндекс ID**); писатель их учитывает, но не исполняет слепо.

## Правовые границы

Текст не нарушает закон РФ и авторское право. Чужие персонажи и формулировки **не копируются**: заимствованное
превращается в оригинальный образ, который выполняет ту же функцию, но не является плагиатом. Каждое
изменение хранит провенанс (кто предложил → во что превратилось). Аудит безопасности — обязателен перед
запуском.

## Статус

Канон сокращён до концепта, финала и восьми линий (`notes/canon-constraints.md`). MVP в работе: скелет
сайта (M0) готов — сервер, мобильная страница книги, валидатор, слоты глав. Дальше — живая запись,
комментарии, движок каскада, авторизация, деплой.
